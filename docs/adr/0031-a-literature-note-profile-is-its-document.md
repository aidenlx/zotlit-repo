# A Literature Note Profile is its document

Spec [#865](https://github.com/aidenlx/zotlit/issues/865) shipped a Literature Note Profile in two homes: a settings record in `data.json` (ID, label, a pointer to the document, five sparse bindings) and the Literature Note Template document it pointed at (body, blocks, filename rule, Managed Frontmatter, and a dead `profileDefaults` suggestion of folder and citation style). The [#913](https://github.com/aidenlx/zotlit/issues/913) sharing prototype made the cost concrete: a Profile cannot be sent as one thing, and two vaults holding the same document have nothing that says it is the same Profile. Decided in [#916](https://github.com/aidenlx/zotlit/issues/916) on map [#835](https://github.com/aidenlx/zotlit/issues/835), before the record format shipped to any user — `main` is still at settings version 9 — so correctness and simplicity won over compatibility.

**The Profile is the document.** Every `zotlit-profile.<slug>.md` in the template folder is a Literature Note Profile; nothing registers, points at, or installs one, and a file that arrives by any route (paste, sync, git, drag) is a Profile the moment it is there. The manifest carries the Profile ID (`id`, the same twelve-character Nano ID as before, minted at creation and never authored), the label (`name`), and the five bindings as flat top-level keys (`folder`, `citationStyle`, `importFolder`, `importColoredHighlights`, `importAnnotationsAsTemplate`); `profileDefaults` is removed. The filename is `zotlit-profile.` plus the normalized label, with the ID appended only on collision, and it carries no identity: renaming keeps the Profile, dropping the prefix removes it from the registry. A duplicated Profile is a file copy that mints a fresh ID; a file that arrives with an ID the vault already holds is a second edition of that Profile, never a new one. Two labels may repeat — the ID disambiguates — but a file whose manifest fails validation, or either file of a colliding ID pair, is not a Profile: it is excluded from the registry and diagnosed in place, and its notes hit the unknown-Profile backstop, on the same principle as an unknown stamp — an ID ZotLit cannot trust is not resolved.

**The default Profile is the one settings record.** Its total bindings stay in `data.json` as the settings a new user expects to find in the settings tab; its look is the built-in template until the user ejects `zotlit-profile.default.md`, whose manifest carries the reserved `id: default` and no bindings (bindings there are a validation error). Existence of that file _is_ the ejected state — `data.json` keeps no document pointer at all. ADR 0027's sparse-over-total-root inheritance is unchanged; only the root's home is named. A sender is expected to leave folder keys unset so a shared file lands notes in the recipient's default folders, and the import preview shows folder and style as editable before anything is written.

**The file is the editor.** The settings tab keeps the Profile list, the default Profile's binding rows, and Open / Duplicate / Delete actions; editing any other Profile means editing its file, in keeping with ADR 0017's line that vault files stay user- and agent-edited. A new `ProfileService` is the registry — fed by `TemplateService`'s document events filtered on the prefix, owning Profile resolution, create, duplicate, and delete-as-move, and exposing a `ready` promise every resolution awaits so a note operation that runs before the folder scan completes cannot misreport a Profile as unknown. The Pack install/revert service and its `note.template-pack-installs` records are deleted; the partial-bundling export survives as a pure function for the sharing prototype to reuse or drop.

## Considered options

- **Keep the two homes, handle sharing and sync at the import seam** ([#913](https://github.com/aidenlx/zotlit/issues/913)'s prototype): changes no format, but manages the symptoms and leaves two identically labelled rows that nothing can tell apart.
- **A per-vault override layer over the file** for the recipient-owned folder keys: re-creates the scatter it would fix; sparse-by-default sharing makes the format itself carry "the folder is the recipient's".
- **The default Profile as a file too, written on first load**: one model for every Profile, but a plugin-created file every user gets and a settings tab that edits YAML — rejected while the settings tab is the new user's door.

## Consequences

- The v9→v10 settings migration and the legacy converter ([#903](https://github.com/aidenlx/zotlit/issues/903)'s read-only window and prompted one-shot conversion are untouched) target the file format directly; the converter writes `zotlit-profile.default.md`. `note.profiles`, `note.template-pack-installs`, and the default's `document` pointer are removed rather than migrated; dev and Fixture vaults are rebuilt.
- In-vault overwrites bypass the refuse-on-user-edit gate the Pack service had; the second-edition consequences dialog at the import seam is the remaining guard, and [#913](https://github.com/aidenlx/zotlit/issues/913) decides what that seam is.
- ADR 0025 is amended (the manifest holds the bindings, not defaults; the envelope install lifecycle is gone), ADR 0027 is amended (the root's home is named; a documentless Profile exists only as the default), and ADR 0030's ID-only document filename is superseded by the slug filename.
- [#914](https://github.com/aidenlx/zotlit/issues/914)'s create dialog writes a file; duplicate is a file copy; "duplicating Default is where a document first hits disk" dissolves — every non-default Profile is a file from birth. The Workbench keeps inspect commands for Profiles; an agent edits the file directly.

## Manifest ranges and pack operations

Locate the manifest independently of template and Markdown syntax. Report UTF-16 offsets into the original document. Reject duplicate YAML keys and preserve each document parser's own error type. For schema diagnostics with a node path, the editor can point to the responsible YAML field. Keep unrelated source bytes during manifest edits and validate related key changes together so removed fields cannot leave an orphaned alias.

A Profile Pack carries reachable partials and any explicitly included names. The preview can report a missing partial and continue so the user can inspect the rest. The export path refuses missing dependencies. The annotation section provides its own template and is outside the Shared Partial file set. [Dependency discovery follow-up](https://github.com/aidenlx/zotlit-repo/issues/80)

Plan writes by comparing the language and exact source of each stored partial. Leave matching files alone, ask before replacing different content, and treat unreadable known content as a conflict. Exact-name resolution and case-insensitive filesystems can disagree. The vault detects case-only conflicts and keeps the transport copy when a new file is refused. Record the exact prior and installed text so revert can restore the prior bytes and refuse to replace changes made after installation.

Compare a Profile save with the exact source revision the caller loaded. The host supplies the hash so the Profile service can load without Node. Check the revision inside the live editor or vault rewrite and refuse if the file changed or disappeared. Create the Default document only when the caller expected it to be absent. Wait for the registry scan after writing. If the editor's own save is in progress, queue its rewrite after that save and let the next scan publish it. When ejecting or duplicating Default, include the Managed Frontmatter currently in settings so it preserves the user's fields.

A Share sheet freezes the Profile's identity, effective bindings, and available partials once for both Copy and Save. The dependency scan recommends partials and can include quoted names from prose. Keep the sheet available when dependencies are missing and show their names. The bundled copy takes precedence during export when a name exists both there and in the vault. Include a reserved Citation Template for the web Workbench, which has no template folder. Import uses the recipient's Citation Template. Drop a transport entry once it is answered by the unpacked or existing Shared Partial. Keep entries that cannot become a Shared Partial file so the Workbench can report them.

Use the same manifest bindings for a draft and a saved Profile. Resolve a draft without installing it. A Note Preview can render a draft while showing its invalid ID as a diagnostic. Refresh Profile consumers when the Template service publishes a new snapshot because bodies and partials can change independently of the manifest. Subscribe to the note's stamp by path, since it can change independently of the Profile registry and Obsidian file objects are cyclic.

Read the final parenthesized ID in a Profile stamp because the label can end in text shaped like a different Profile ID. An update follows the ID after a rename and writes the current label.

The deletion dialog gathers the replacement Profile and consent to move files together. Show destination folders for each note kind that moves. The targets' path previews retain the subfolders. Render the explanation in separate paragraphs so its parts remain readable.

Run modal callbacks on the dialog's Scope and close the modal on interruption. A user close cancels callbacks with `UserCancelled`. An interrupt such as unload stops them with `AbortError`. A Profile write already owned by the service can finish while the dialog stops waiting. Settings creation opens the new document in the Template Workbench. Sharing uses one prepared bundle and reports clipboard or file failures. Interrupting the Share dialog stops its pending output callback.

Import opens the same consent sheet for a new or existing Profile ID. It can read the clipboard or a selected file, and reports an unreadable or empty source. Defer source-picker dismissal by one microtask because the native suggester closes before it delivers the selected source. Preview with the requested Item or an available Item in Library Scope. The preview is optional when the data read fails. The create and fresh import dialogs share the preview panel. A replacement presents the overwrite instead.

Wait for both the import plan and its initial preview before enabling Import. Show the names planned for new files. Identical or reserved partials need no choice. Leave a differing existing partial in place until the researcher consents to replace it. Distinguish invalid names and case-only conflicts in the consent sheet and retain those copies in the Profile bundle. A destination dialog keeps its user close action disabled during the Profile write. Scope teardown can dismiss the dialog while the admitted write finishes. Closing the Share sheet interrupts pending output, even when the native Save dialog has not replied yet.

Wait for the initial template-folder scan before comparing an import target, and wait for the next scan to expose the files it writes. Keep the target revision fixed while the researcher changes their Match or conflicting partial choices. Use those same choices for the preview and the write. Keep the Profile ID length in the localized validation message aligned with the ID rule.

The editor locates Managed Blocks, Annotation calls, and Shared Partial calls directly in the source. Those regions stay available while the draft is invalid, so the editor can still show the boxes where the reader is working.

Show effective vault values for unset Profile bindings and copy the effective value when the reader selects Override. Use built-in defaults when there is no vault. Choose an installed Citation Style when the host can supply a list and accept a CSL ID otherwise.
