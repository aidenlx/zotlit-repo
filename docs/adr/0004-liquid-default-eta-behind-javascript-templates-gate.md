# Liquid is the default template language; Eta lives behind the JavaScript Templates gate

Templates are shareable vault content, and under Eta every template is a full-privilege script (`new Function` at compile time) — the pattern Obsidian's scorecard flags as "dynamic code execution" and the Obsidian team advised the Tasks plugin to disable by default after an RCE report. We decided v2 renders templates with LiquidJS (a pure AST interpreter, no eval anywhere) as the only documented default, and keeps Eta as a power-user tier behind an explicit **JavaScript Templates** opt-in: off by default, stored per device via `app.saveLocalStorage` (never synced, so a shared vault or synced `data.json` can never pre-enable it), consented through a one-time confirmation modal. The one toggle gates the entire dynamic-code surface — Eta template files _and_ JavaScript frontmatter fields. Each Managed Frontmatter field declares its expression language explicitly (Liquid value-expressions via `evalValueSync` with types preserved, or JavaScript); the gate never reinterprets an expression, it only decides whether JavaScript fields run. While the gate is off, the plugin attempts no dynamic code compilation or execution anywhere: an operation that requires an inert artifact (an Eta template or a JavaScript frontmatter field) fails with an error naming it rather than falling back to substitute output, and even settings validation of JavaScript expressions waits for the gate.

## Context worth remembering

- The switch happened at v2 alpha deliberately: the v1→v2 migration was already breaking and no user had an investment in v2 Eta syntax yet. Post-2.0 this would have been a second breaking migration.
- Amended 2026-07-11 (pre-ship, in place): frontmatter was originally specified as gate-switched — one language for the whole field set, flipping with the toggle. Revised to per-field explicit `language` because the gate is per-device while the field settings sync, so gate-switching made one synced configuration mean different things on different devices. Existing fields are stamped JavaScript by a settings-data migration (old-default expressions translated to the Liquid defaults), and a gate-off device forbids authoring or validating JavaScript rather than warning about it.
- Amended 2026-07-12 (pre-ship, in place): inert artifacts were originally degrade-and-notify — an inert Eta template fell back to the embedded Liquid default and inert JavaScript fields were skipped, both surfaced via aggregated Notices. Revised to blocking typed errors (no implicit fallback): a note built from a template the user didn't choose, or written with part of its configured frontmatter missing, is silent policy substitution — worse than a refusal that names the artifact and the fix. Runtime-error isolation for throwing field expressions is unchanged; that's the author's own bug reported loudly per field, not policy substitution.
- Amended 2026-07-13 (pre-ship, in place): embedded defaults were originally shipped in Liquid only, with the Eta editions demoted to migration-doc reference material and the language dropdown creating an _empty_ `.eta.md`. Revised to ship both editions for all six templates (the `filename` Eta edition recovered from its former `template.filename` setting default), because starting an Eta template from a blank file strands the user who chose Eta for a small tweak. Toward-Eta populates from the Eta default; reset follows the file's own edition (Eta reset writes the Eta default, gated on the JavaScript Templates flag); eject stays Liquid-only. The two editions are held byte-parity by the defaults test suite.
- Both engines bind template data to `zt` (Eta's `varName` is overridden from its default `it`), so `zt.…` is the single data vocabulary — the variable name is deliberately _not_ a Liquid/Eta tell. The Data Explorer offers one `zt.…` copy-path regardless of the gate; there is no `it` alias, and a stray `it.foo` fails loudly. Path syntax (`.name`, `[i]`, `["special-key"]`) is valid in both engines, so one copied path pastes correctly into either.
- A LiquidJS prototype reproduced all v2 default templates output-equivalent: the `{% bq %}` block tag matches `bq()` byte-for-byte, `outputEscape` replicates the null/Temporal filter, `{% liquid %}` statement blocks handle logic-heavy sections with zero whitespace leakage, and LiquidJS invokes zero-arg function properties, so the link-helper data model (`{{ a.fileLink }}`) ships unchanged.
- Liquid truthiness (`""` and `0` are truthy) is the recurring footgun; the mitigation is normalizing empty strings to `null` when building `zt`.
- The template file extension names the language (`zotlit-<name>.liquid.md` / `.eta.md`); when both exist, Liquid wins and the Eta file is flagged as shadowed, so effective rendering never depends on the device-local flag. Includes resolve by template _name_ through TemplateService, which dispatches per-name to the winning file/engine — mixed-language sets work, and include semantics live in the service rather than in eta codegen patching.
- The filename template moved from the `template.filename` setting string to a vault file for the same reason as the gate: a JS expression in `data.json` syncs, which would have bypassed the local-only consent.
- The scorecard flag does not disappear — static analysis keys on the presence of `new Function`, not on toggles. Disabled-by-default plus disclosure is the accepted posture per the Tasks precedent.

## Considered options

- **Handlebars / Nunjucks**: rejected — both compile templates through `Function` at runtime, so for vault-loaded user templates (precompilation impossible) they deliver zero eval-safety over Eta, while costing more helpers to express the same defaults.
- **Liquid-only, remove Eta**: rejected — burns the v1 power-user migration path and forecloses Templater-style customization; the ceiling would be re-litigated under pressure.
- **Sandboxing Eta (SES / ShadowRealm / wasm engine)**: deferred, not rejected — heavy machinery, easy to get subtly wrong, and the Obsidian team has signaled a possible official sandboxed-eval API. The gate leaves a seam: a future sandbox slots in behind the same toggle as a hardening upgrade without touching Liquid users.

## Rendering adapters

Liquid and Eta share output coercion and blockquote formatting. Missing values render as empty text, JavaScript Dates render in ISO form, and a Temporal Instant renders as a local calendar date. Other values can supply their own string conversion, as ItemDate and creator values do. In Liquid, this output adapter applies to interpolation but is bypassed by the echo tag. The engine reports unknown filters and uses line-sensitive whitespace trimming so a trim marker can preserve an adjacent blank line.

The Liquid date filter converts supported Temporal and multipart date values before delegating to LiquidJS. Calendar-only values use local calendar components so time-zone conversion does not move the date. Text-only ItemDate values keep their original text. Structural typing lets the adapter accept the database value without importing the database package. [Early year follow-up](https://github.com/aidenlx/zotlit-repo/issues/82)

Pass an in-memory filesystem when a facade owns partial resolution. Omit the filesystem option entirely when using LiquidJS's default, because an explicit undefined value displaces that default. Link filters accept nullable helpers. The embed wrapper omits a missing link and lets a prepared excerpt supply its own unavailable text. Related note links retain the legacy per-item error marker when the item has no note link. Tag conversion reads the tag object's name, preserves characters outside Obsidian's tokenizer exclusions, collapses repeated separators, and prefixes an all-digit tag with an underscore. The array replace filter refuses an empty search so the replacement cannot be inserted between every character.

Legacy Eta includes pass their data directly, including arrays. Eta spreads the data in generated helpers before its render override can see it, so the adapter rewrites the exact synchronous and asynchronous helper strings. A missing match fails compilation so an Eta upgrade cannot silently restore spreading. Named renders and includes share the output transform. Compiled-function calls carry no registry name. The facade enables Eta's runtime diagnostics to keep a name, line, and source excerpt. For each side of an Eta tag, `nl` trims one line break, `slurp` trims all whitespace, and false keeps it.

Name the inert artifact when a render is refused. A refusal to use the whole managed-frontmatter field set carries no template name because the fields are not a named Template.

Show the JavaScript Templates toggle as a service-backed control because its value is per device. Apply permission changes through the template rebuild so views see the compiled state that matches the control. Confirm before turning it on and apply turning it off immediately.

Report an Eta edition shadowed by Liquid as shadowed regardless of consent. When Eta would win and consent is off, leave that name without a compiled template. Rendering it raises the typed inert-template error instead of rendering the bundled default.
