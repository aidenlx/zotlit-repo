# Imported Notes render under Profiles with explicit stamps

> **Amended by [ADR 0079](0079-the-literature-note-body-is-the-users-and-rendering-has-no-side-effects.md).** Side-effect imports no longer exist, so the stamp comes only from an explicit import: an item-attached note copies the parent's Literature Note stamp, and any other note gets the default Profile.

> **Amended by [ADR 0035](0035-profile-annotation-section.md).** The required final Annotation Section replaces the Annotation Block and supplies all annotation rendering under its Profile. Profile inheritance and stamps remain unchanged.

> **Amended by ADR 0031.** The inheritance model stands; ADR 0031 names the root's home: the default Profile's total bindings record is the one settings record, and every other Profile's sparse bindings live in its document's manifest. A documentless Profile no longer exists except the default itself, so the "deferred default-Profile-document work" is the eject of `zotlit-profile.default.md`.

Spec [#865](https://github.com/aidenlx/zotlit/issues/865) kept Imported Notes outside the Profile system (one global folder; "Profiles for Imported Notes" out of scope). The [#876](https://github.com/aidenlx/zotlit/issues/876) grilling overturned that: an Imported Note is created and re-imported under a Literature Note Profile, and the Profile — not vault-global settings — supplies its import folder, colored-highlights and annotations-as-template behavior, display-layer citation style, and annotation template.

**Explicit stamps, no implicit inheritance.** Every Imported Note carries the same `zotlit-profile` system frontmatter stamp as a Literature Note. The stamp is written once at creation from the creation context — a side-effect import uses the in-flight operation's Profile; an explicit import of an item-attached note copies the parent's Literature Note stamp; a standalone note (or an attached note whose item has no Literature Note) gets the default Profile — and is re-emitted on every whole-body overwrite. After creation, writes follow the stamp: changing the item's Profile changes nothing about its Imported Notes, and an absent stamp means the default Profile, never "ask the parent." The considered alternative — a dynamic chain (own stamp → parent's stamp → default) resolved at every write — was rejected as too implicit: a note's behavior could change because a _different_ note was edited. The interactive Profile switch on a Literature Note may offer "also switch this item's imported notes" as an opt-in; headless surfaces follow stamps, and no import surface accepts an explicit Profile parameter.

**The default Profile is the one inheritance root.** Profile bindings widen to five sparse keys (literature folder, citation style, import folder, colored highlights, annotations-as-template); a Profile that leaves one unset inherits from the default Profile, whose bindings record is total. The vault-global settings keys behind all five retire through a silent settings-shape migration on load — users configure note behavior in exactly one place. The import folder applies at create time only; re-import overwrites in place and never relocates a file.

**The annotation template moves into the Profile document.** An exactly-one `{% annotation %}` … `{% endannotation %}` block in the Literature Note Template document's body replaces the global `annotation` slot: isolated render scope, Annotation Root data, stripped entirely from create-time body output, rendered only on demand (drag-insert resolves the annotation's parent item's stamped Profile; Annotation Paragraph subsuming uses the Imported Note's Profile). A document-scoped block was chosen over a designated global partial so the template travels inside the Pack and the flat partial namespace ruling stays intact. The prompted one-shot converter folds an ejected `zotlit-annotation.*.md` into the default Profile's document with byte-identical verification; an un-ejected slot seeds the embedded default's source as a trailing block, unverified — copying the default needs no proof against itself. `cite`/`cite2` remain the only vault-global template slots.

**The Annotation Block is required** (amended in the [#880](https://github.com/aidenlx/zotlit/issues/880) push-back grilling; originally zero-or-one with "absent block = embedded default"). A document with zero blocks fails validation before any write, exactly as a duplicate does, and a blockless Pack is refused at install; block position carries no meaning — create-time stripping makes it invisible to output — and generated documents place it last by convention. The embedded default retires as a render-time fallback and survives only as seed content. The asymmetry with the Managed Block is deliberate: a Managed Block's absence has visible meaning (a static body), while an Annotation Block's absence would silently substitute hidden content — the implicitness this decision cluster exists to eliminate. A documentless Profile predates the rule and keeps serving the embedded default through the legacy slot machinery; once every Profile has a document (the deferred default-Profile-document work), the embedded default's render path dies entirely.

ADR 0001 stands: Imported Notes are mirrors with whole-body overwrite — the Profile parameterizes the conversion, not the update contract. This extends ADR 0025's document format with the Annotation Block. Decided in [#876](https://github.com/aidenlx/zotlit/issues/876) on map #835; consequences flow to [#877](https://github.com/aidenlx/zotlit/issues/877) (Workbench annotation commands become document-aware) and [#878](https://github.com/aidenlx/zotlit/issues/878) (the Templates settings surface shrinks to `cite`/`cite2` plus engine config).

## Child Note conversion

Use schema 6 or later for linked Zotero marks. This lets the parser rely on the modern annotation and citation payloads. Look for the schema element at any depth so notes read from SQLite can retain their storage wrapper. Convert the schema element's children and read its hoisted citation data before conversion. Use Zotero's leading-integer version parsing, including when text follows the number. Use Plain HTML conversion when the marker is missing or invalid. Report a known version below the minimum with a legacy-format callout.

Promote a direct-child paragraph with a leading Annotation excerpt and only supported trailing elements to a callout. Render the Annotation text and comment from Zotero's Annotation record. Leave nested paragraphs in their original lists, quotes, or table cells so a callout does not break their structure. Keep the image excerpt's embedded image key separate from the source Attachment URI. Use the embedded CSL snapshot when the live citation lookup cannot resolve a reference. Link an unavailable excerpt with its Durable Annotation Link so it works across devices.

Build a Turndown instance per conversion so its rules can use the current note's resolvers. Inject Obsidian's runtime Turndown constructor and use the npm build in tests. Keep the base Obsidian Markdown rules, including literal math delimiters and unescaped markers. Add Zotero's styled strikethrough spans, bare code blocks, inline HTML for subscript, superscript and underline, and the color marks. Resolve attachment images, citation marks, and Annotation spans through the per-conversion rules. Standalone conversion preserves the raw marks for later resolution. Pass pre-rendered callout Markdown as an encoded attribute because Turndown collapses whitespace in DOM text.

Read cited Items and attachment rows before conversion so Turndown can run synchronously. Find eligible Annotation paragraphs with the same scan before reading the rows and before converting. Render those callouts in one batch of distinct keys in document order, with the destination note's attachment batch already bound. Replace accepted paragraphs before the image rule runs, so it cannot copy a storage image that the callout replaces. Use a zero-width placeholder in the detached document's sentinel to pass Turndown's blank-node check. Keep declined or blank callouts on the inline path so their original content survives. Limit blank-run normalization to the rendered callout so the source body's code and math blocks retain significant whitespace. [Child Note parser](../../packages/notes/src/desktop/note-import/note-parser.ts)

Pass each embedded image's resolved path and source origin to the attachment decision port. The port owns approval and copying. URL attachments and unknown path formats have no local path to pass. A malformed Annotation payload keeps the converted text. A valid mark with a missing attachment reference keeps its formatting without a backlink. Parser tests run the real conversion rules with fixture rows and a decision port that blocks copying. The batch renderer fixture retains blank results to exercise the prepass guard. [Child Note parser tests](../../packages/notes/src/desktop/note-import/note-parser.test.ts)

Use a theme color variable with the raw color as fallback so a snippet can override a mapped color. Use raw color for an unmapped color, retain the class for a colorless mark, and use Colored Highlight Syntax where the option and mapping permit it.

Overlay a Profile's sparse bindings on Default. Keep the Profile's own citation style separate from its effective binding so the note's style stamp records only an override. When a note moves between Profile folders, preserve the part of its path under the source folder. Use the filename alone when the source Profile is unknown or the note is outside its folder.

Ask for consent before moving or stamping the note family, including the option to apply the Profile to Imported Notes. A Profile made in the picker joins the plan. A switch changes the stamp for the next update. Removing the stamp selects Default. Finish the move, stamping, and rollback even if the caller is interrupted. On failure, restore stamps in reverse write order, including the failed write because it may have reached the vault, then restore the path. The current rollback can read an out-of-date stamp from the metadata cache. [Issue 153](https://github.com/aidenlx/zotlit-repo/issues/153)

When a Companion request omits a Profile, accept an existing note with its current stamp. An explicit Default is a real selection and conflicts with a different stamp.

Batch confirmation prepares each Imported Note's Profile and path before writing. Offer a Profile choice for new orphan notes and prepare the replacement paths only for those rows. Run the choice callback over the same service context as classification. Record an unresolved Profile stamp in the preview and let execution report its write diagnostic. [Batch import runner](../../packages/notes/src/desktop/note-import/batch-import.ts)

Use the parent Literature Note's Profile when creating an attached note with an indexed parent. If the stamp is unknown, locate the note whose stamp caused the refusal so recovery targets that Literature Note or the existing Imported Note. Fetch Annotation sources for the prepass keys in the note's Library. The renderer uses that result and the note's own attachment batch. [Note Import write service](../../packages/notes/src/desktop/note-import/service.ts)
