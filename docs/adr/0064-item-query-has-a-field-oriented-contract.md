# Item Query has a field-oriented contract

> Amended 2026-10-10 by ADR 0071: `attachments` and `annotations` of an Item are Relation Lists of records, Attachment Query is a third Query Dataset, `library` is a field of every dataset, and a Projection Path reaches a list element with an explicit `[]`.

`@zotlit/item-query` accepts one full Filter Expression for selection and one or more Target Libraries. The Items of all Target Libraries are filtered, sorted, and limited as one result set; each Zotero Key, Tag, and Collection path matches inside the Library of its Item. Projection accepts documented template-style accessors, sorting accepts top-level scalar Item fields, and each result row contains only the selected values plus the Item's Indexed Key. This contract gives human and agent callers predictable data without exposing the database Item structure or introducing computed-column syntax.

The evaluator adopts the proof of concept's ZotLit-owned semantics for field aliases, custom fields, relations, partial dates, Temporal values, null propagation, and functions. Obsidian Bases compatibility is not part of the contract.

Query Rows use ZotLit's template base-data vocabulary. Item Query extends it with collections, attachment presence, and a `custom` object that preserves exact custom-field names without colliding with reserved fields. Its wire adapter serializes Temporal values as ISO strings. This preserves source values such as `date.raw` while allowing precise Projection Paths such as `date.year`.

Filtering, projection, and sorting have explicit capability vocabularies. Filters retain the proof of concept's evaluator values, including string lists for creators, tags, and collections. Projection exposes the richer template base-data structures. Sorting accepts top-level scalar fields only. `accessDate` has one value in all three: a timestamp, or a calendar day when Zotero stores only a day, and a calendar day sorts from its start in the query time zone. The query schema states which operations each field or path supports.

Filter requests are validated against that schema before database execution. An unknown field, function, or unsupported capability fails the complete query, while a known field that one Item lacks evaluates as null. Arbitrary custom-field names use `custom["exact source name"]`; identifier-safe, non-colliding custom fields can also retain their bare-name filter form.

Each Query Row has the shape `{ indexedKey, values }`, where `values` is a flat map keyed by the requested Projection Paths. Paths use the template accessor grammar: dotted identifier access, numeric array indexes, and JSON-quoted brackets for arbitrary keys. Array access is exact and does not vectorize implicitly.

Every requested Projection Path is present in `values`. A missing scalar, custom value, or array element is null, while an Item with no values for a requested relation list returns an empty list. A path that the schema does not define is a request error.

Six edge policies refine the adopted semantics. A known function with a wrong argument count or a wrong literal type fails the complete query, while a failure that depends on one Item's data evaluates as null. Null is falsy wherever a filter reads a truth value: the match, `&&`, `||`, an `if` condition, and the operand of `!`, so `!x` is true when `x` is null. Each query uses one instant and one time zone, and that zone defines every calendar day. String equality and matching are exact, with no type coercion; ordering uses one fixed root-locale collator. A bare name that matches a built-in field, alias, or reserved name always means the built-in. Relation lists keep one element for each source row, and a Collection element is its root-first path.

## Projection and grouping

Projection accepts dotted identifiers, numeric brackets, JSON-quoted keys, and the exact `[]` token. Keep the source offset of each accessor so validation can locate a failed segment. Read quoted strings as a unit when finding the closing bracket, which lets a key contain a bracket. Numeric access takes one element. Empty brackets apply the remaining path to every element, preserving order and null positions. An absent key or element projects null. Check requested custom fields against the active source after planning the path.

A group path names a scalar or uses one `[]` to reach scalar elements. A record enters each distinct non-null element group once. An empty list or one with only null values enters the null group. Apply the row limit within each group. Explicit numeric access does not project across a list.

## Field registry, labels, and sort keys

The registry supplies each field's shape, hydration needs, and operations. The shape determines legal Projection Paths and the JSON types in the Query Schema. A Query View can display a scalar or a list of scalars as one cell, including eligible paths through records. Parent and list records use their dataset's vocabulary at every depth, and their navigation propagates hydration needs back to the root. Use callbacks so mutually referring record vocabularies can resolve lazily. List representative paths without repeating a path already available on the current record.

Keep field Search Terms in the field picker vocabulary. Search Terms can help find a field but do not give it another name in a filter. For Zotero fields, use their names, bundled translations, and related type-specific field names. A parent path uses the parent dataset's words, and an ordinary path under a field inherits that field's terms. Match the start of the term or one of its words, with substring matching for Han text because it has no word separators. Skip scattered-letter matching so the full vocabulary does not overwhelm results.

The projected sort-key conversion and the runtime sort share one rule. A Zotero multipart date sorts by the first day its precision permits, so a bare year can tie with January 1. A calendar-only access date starts at midnight in the Query Clock's time zone. An unreadable stored timestamp is absent in projection, filter, and sort. A Creator sorts by family name then given name, and a one-field name sorts as family. Stored-string candidate lowering can use base-field aliases only when the registry's filter reader uses that stored value.

## Filter planning and evaluation

Use one validated tree for candidate planning and evaluation. It carries resolved names, each node's static type, and the fields that hydration must read. An unknown type depends on the record at evaluation time. Validate every argument of a call, including the unused branch of `if`. A bound element name takes precedence over a field. A list method plans and evaluates its element expression inside the `value`, `index`, and, for `reduce`, `acc` scope. Evaluate the other arguments once outside that scope. When a name also selects an ordinary method, use the receiver type to choose its implementation. A lookup in a literal list can use a membership index built once at planning time.

Use exact bracket access to disambiguate a custom field. A bare identifier can resolve to a source field after that source supplies its names. Only an identifier chain can have an ambiguous dotted source-field spelling. Reserve `formula` as the first segment of a Formula reference.

Keep Zotero field values as text, even when SQLite stores a number. RegExp literals are available during evaluation and stay outside Query Rows. Treat null, Error Values, and empty lists or durations as falsy. Logical operators evaluate an operand only if it is needed. Equality compares strings by code unit, lists element by element, records by identity, durations by unit, and regular expressions by pattern and flags. An Error Value equals no value. Arithmetic propagates it and yields null for missing operands. String concatenation renders null as empty text. Use the same fixed `en` collator for sort, ordered comparisons, and Tag and Collection ordering so the host locale cannot change the result. Scalar order is boolean, number, string, then null.

Use the Query Clock for wall-clock timestamps, date arithmetic, and calendar-day comparisons. Two timestamps compare as instants. When either value has calendar precision, compare closed day intervals in the query time zone. Equality means overlap, and strict ordering requires disjoint intervals. A parsed Zotero text date supplies its recognized year if it has one. Stored `accessDate` accepts UTC date-time text or a calendar day. Durations accept ISO 8601 or unit shorthand, with weeks folded into days. Calendar-only arithmetic preserves the date's precision and can shift its first day within the resulting month or year. Sub-day arithmetic returns a timestamp. A partial date exposes calendar parts at its precision and renders at that precision. Relative text uses the same clock and counts calendar days for calendar dates.

## Evaluator edge cases

Each source Creator row contributes one element, even when the same person has multiple roles. A Collection uses its root-first path, and `within` includes the selected Collection and its descendants. A nested element expression shadows only the names it binds. Validate its expression even for an empty list. The index binding has a known numeric type and the value and accumulator can depend on the record. An Error Value in an extra argument is the method result even if the element expression would ignore it. Error Values can answer `isType()`, `isTruthy()`, and `toString()`.

Keep list sorting stable. The sort groups values in this order: boolean, number, text, date, duration, list, regexp, record, Error Value, and null. Compare dates by their start at full precision. Values with no within-group order keep their input order. A date interval uses the full month or year containing the day produced by arithmetic. A timestamp and a calendar date compare in the query zone. Adding a calendar month can clamp a day at the month end. Zotero date text falls back to a year in 1000–2999, and a malformed day in a structured date falls back to the month when valid.

Use literal text matching for SQL wildcard characters and the fixed collator with lexical digit order. Use JavaScript lowercase mapping, including the combining dot produced by capital dotted I. Title case changes the leading code point of a whitespace-delimited word and preserves the rest. Reverse by code point. Length, slicing, and index access count UTF-16 code units. Repeat accepts an integer from 0 through 10,000 and caps the resulting string at 1,000,000 code units. Text replacement applies literal replacement text to every match of a text pattern. A regular expression pattern uses JavaScript flags and capture substitutions. Reset its match position on each evaluation, including each element in a list expression. Split includes captured separators and counts them toward the result limit. An unmatched capture yields null.

In `packages/item-query/src/filter.test.ts`, compare indexed literal-list membership with the scan through `.filter(true)`. This keeps the same elements but makes the receiver nonliteral. Check the large-list match count in the unit test. Measure elapsed time in a benchmark because machine load can change it.

Type-specific field values take precedence over the stored base field. A same-named custom field is separate and field lookup is case-sensitive. A Collection leaf name alone identifies only a top-level Collection. Descendants of a trashed Collection stay outside the visible paths. A missing first author sorts last and an Indexed Key breaks ties. The Indexed Key compares as text, including the group suffix, and a bare Zotero Key names an Item inside each Target Library.

Use a single clock read across a query. A calendar-only access date sorts from midnight in the query zone, so its position relative to a stored UTC timestamp can change with the zone or daylight saving. The access date filter compares date values.

Check an ambiguous dotted field against the active source. If its prefix exists, the suffix keeps its property meaning. Otherwise report the invalid dotted access and suggest the exact bracket form when the source has that dotted field. The same rule applies to reads through the `custom` namespace.

Use the same Projection Path text formatter in the Query View and the CSV and TSV exports. Render a Formula Error Value as its `toString()` text. For a Zotero multipart date, prefer its display text and fall back to the part of the stored value after the first space. Use the available name for a Tag, Collection, or Creator.
