# @zotlit/zotero-compat

The functions that reproduce a value that the Zotero client computes from a record, and the client data that they read. The importer of the Web Library Replica (`@zotlit/db/replica`, `src/replica/apply.ts`) calls them and keeps the SQL. This package is the one place to compare ZotLit with the Zotero client: its tests are the compatibility record.

- The reference is zotero/zotero at commit 213b0d7d7 (AGPL-3.0; `NOTICE` names each derived file). Its `chrome/content/zotero/xpcom/utilities` is the submodule zotero/utilities at commit 4051881d5. Cite that copy; `xpcom/translate/modules/utilities` is an older copy with other line numbers.
- The package is in the Worker zone (`zotlit.layer: "worker"`): no DOM, no Node built-in, no host module, no SQL. The runtime check (`pnpm run lint:runtime-zones`) holds this. Tests and `scripts/` run in Node.
- The package depends on no other ZotLit package.

## Interface

Each function takes the value of one field of a Web API record and the context that the client reads from its environment as explicit arguments: the time zone, the current year, the client language. It gives the value that the client stores. `undefined` or `null` means that the client stores no value; the importer chooses what to do then (log, leave out, or use the time of the apply).

File paths are under `chrome/content/zotero/` unless they start with `test/`. The other cases of each test file are hand-derived from the client source; each test name says which client behaviour it holds. Keep each expected value unless the client changes.

- `strToMultipart` resolves the requested language as the client does and compiles the month and day patterns of each resolved language once. `en-US` is the one default (`DEFAULT_DATE_LOCALE` in `src/date-locale.ts`).
- The client trims and normalises (NFC) a field value, a creator's first, last and single name, a tag name, a collection name and the annotation author name, text, comment, colour, page label and sort index. It does not normalise the note HTML (`cleanNoteText` trims it and removes control characters), the annotation position, the relation URIs or the attachment file name, path and content type.
- The month names and day suffixes go into the patterns unescaped, as the client builds them: `ja-JP` month names add capture groups, and a `.` suffix (`de`) matches any character. This is an exception to the regex rule of escaping dynamic text, kept for fidelity; `src/multipart-date.test.ts` pins the `de` case.
- The month pattern uses the runtime's letter class `\p{L}` and counts a letter outside the Basic Multilingual Plane as a separator, because the client matches letters in the Basic Multilingual Plane only.
- `noteToTitle` reads the note in linear time with no recursion and no dependency: it leaves out tags and comments, reads a `>` in a quoted attribute value and an unclosed tag at the end as the HTML tokenizer does, keeps the text of `script` and `style`, and decodes numeric references as the HTML parser does (the replacement table for 0x80 to 0x9F; U+FFFD for 0, a surrogate and a code point above U+10FFFF; a control character or a noncharacter is kept), `&apos;` and the 252 named references of HTML 4 with their semicolon, and the legacy names that HTML also reads without it.

## Known differences from the client

`src/known-differences.ts` holds the rows; `src/known-differences.test.ts` holds each row (the result of this package, and that it differs from the client's). `pnpm --filter @zotlit/zotero-compat generate:known-differences` writes the table below from the rows (`\u{…}` for a character outside printable ASCII), and the generated-artifact step of `pnpm verify` fails when it differs from the commit. `pnpm verify` counts this guide as a source, not as an agent doc (`GENERATED_ARTIFACTS` in `packages/scripts/lib/generated-artifacts.ts`), so a change to it alone still runs that step. Change the rows, then regenerate; do not edit the table. The client's results of the note rows are those of a spec-conformant HTML parser (parse5, which the importer used before 2a04ccf62); the client's result of the month-name row comes from the letter table of the client's `xpcom/utilities/xregexp-all.js`; the client's result of the item-date row comes from `fromJSON`, `dateToSQL` and the setter's `sqlToDate` (`Date.UTC` reads a year from 0 to 99 as 1900 + year).

The second half of the record is the list of tolerant cases in the database guide (`packages/db/AGENTS.md`, Web Library Replica): values that the client refuses and the replica stores, such as an annotation colour or sort index that the client rejects (`xpcom/data/item.js:4535`). They are importer policy, and `packages/db/src/replica/apply.test.ts` holds each one.

The replica has other differences that no function of this package computes (local numeric IDs, columns of local history); the database guide (`packages/db/AGENTS.md`) holds them with the parity tests.

## Client data

`zotero-client/` holds verbatim copies of three files of zotero/zotero: `chrome/content/zotero/xpcom/isbn.js` (the ISBN registrant ranges), `resource/schema/dateFormats.json` (the month names of each language) and `app/assets/multilocale.txt` (the languages that Zotero ships). It also holds `day-suffixes.json`, the `date.daySuffixes` entry of each `chrome/locale/*/zotero/zotero.properties`, which the vendoring command extracts from the same commit (the 48 properties files are 4.8 MB). `zotero-client/provenance.json` records the commit and the extract. `scripts/generate-client-data.ts` writes `src/isbn-ranges.ts` and `src/date-formats.ts` from them; the generated-artifact step of `pnpm verify` fails when they differ from the commit.

## Update to a new Zotero version

1. Copy the client files and the day-suffix extract at the new commit: `node packages/scripts/scripts/vendor-upstream.ts zotero-client <ref>`.
2. Regenerate the tables: `pnpm --filter @zotlit/zotero-compat generate:client-data`.
3. Compare the client functions of the table above with their ports. Change a port together with its source, and update the file:line references and the commits in this guide.
4. Run the tests of this package: `pnpm exec turbo run test --filter=@zotlit/zotero-compat`. Then run the tests of `@zotlit/db`, which hold the replica against the desktop database.
5. A case that now fails is a change of the client: change the port and keep the case, or add a row to `src/known-differences.ts`, with the maintainer's acceptance, and run `pnpm --filter @zotlit/zotero-compat generate:known-differences`. Remove a row that the client no longer differs from.
