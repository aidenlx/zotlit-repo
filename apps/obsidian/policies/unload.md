# Unload

Unload closes the plugin's runtime Scope and every layer Scope under it. The close stops every pending run, and code outside Effect sees that stop in one of two shapes. The reviewer checks each part below.

- **Every run stops.** A bridge run lives in the bridge's Scope (`packages/plugin-kernel/src/effect-bridge.ts`, `bridgeOver`): `effectBridge(runtime)` uses the runtime's Scope, `scopedBridge` the layer's. At unload, `runPromise` rejects with an `AbortError` (`packages/plugin-kernel/src/abort-error.ts`), and `runPromiseExit` resolves with an interrupt-only Exit, which `valueOr` or `settleAtEdge` (`packages/plugin-kernel/src/signal-edge.ts`) maps to the caller's released answer. Where the caller acts on an empty answer (an empty list that shows a "No PDF attachment" notice), the released answer is a distinct value, such as `undefined`, and the caller does nothing for it (`packages/annotations/src/obsidian/attachment-open/handle.ts`).
- **A waiting caller stays silent.** A caller that awaits a run treats the unload's `AbortError` as no outcome: no notice, no log. `toast` (`packages/obsidian-kit/src/toast.ts`) and the notifier's `reportProgress` / `reportOutcome` (`packages/obsidian-kit/src/notifier.ts`) already pass over it; other code tests it with `AbortError.test`. A fire-and-forget call on an edge handle's Promise member adds `.catch(passAborted)` (`packages/plugin-kernel/src/abort-error.ts`). A view forks a fire-and-forget gesture on its view runner (`packages/obsidian-kit/src/view-runner.ts`), whose close ends the run as an interrupt, which reports nothing. A legacy port that rejects with the unload's `AbortError` ends its `portCall` as an interrupt (`packages/obsidian-kit/src/legacy-port.ts`), so Effect code sees unload as an interrupt only.
- **The user's stop has its own reason.** The user's choice to stop work is `UserCancelled` (`packages/plugin-kernel/src/user-cancel.ts`), not an unload: a dialog the user closes stops the work its callbacks started with it (`runDialog`, `@zotlit/notes/desktop/profile/dialogs.ts`). The caller handles it by type and stays silent, and the notifier's `reportProgress` / `reportOutcome` pass over it as they pass over an unload.
- **A call fired and forgotten** from a DOM, editor or observer callback runs through `bridge.runAndForget`: unload stops it quietly, and the bridge logs any other failure with its cause at Error level under the `bridge` category. A failure the user must see is handled by the service or the caller.
- **A write finishes its step.** A write step that an interrupt would leave half-done (a created note before its stamp, a template conversion, a settings save) is an `Effect.uninterruptible` region in its service, so the Scope close waits for that step and no longer: the `write` of `packages/notes/src/obsidian/template/service.ts`, the write regions in `packages/notes/src/obsidian/profile/service.ts`, `flush` in `packages/plugin-services/src/obsidian/settings/service.ts` ([Services](services.md#effect-runtime) → Interruption gives its test). A write whose outcome is known when its layer closes keeps that answer: an accepted send, a refused send (a 412) and an accepted create. A send still in flight at the close answers `unknown-outcome`.
- **A captured runner is scoped.** A service that keeps a runner for later callbacks builds it on a Scope: the layer's `FiberSet.runtime` (`packages/plugin-shell/src/obsidian/protocol.ts`), or `scopedBridge` (`packages/citations/src/obsidian/citekey-reading/service.ts`); the plugin runtime's bridge is `effectBridge(runtime)` (`packages/plugin-shell/src/obsidian/runtime.ts`); a view's runner sits on a Scope of the view's own, closed when the view closes (`makeViewRunner`, `packages/obsidian-kit/src/view-runner.ts`). A protected write keeps its child work on the owning Scope until it finishes; `owned` and `write` in `packages/notes/src/obsidian/template/service.ts` use `Effect.forkIn` and join the fiber, with writes marked uninterruptible. `zotlit-services/scoped-runner` checks every service.
