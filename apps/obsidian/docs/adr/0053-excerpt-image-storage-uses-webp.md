# Excerpt Image storage uses WebP

Use lossless WebP for newly generated ZotLit Excerpt Images in the derived cache and durable note assets to reduce encoded image size while preserving small text, equations, and ink strokes. Encode each generated result once and reuse its encoded bytes for cache storage and note materialization. This refines the PNG format assumption in the design behind [ADR 0049](0049-excerpt-images-use-zotlits-cache-and-renderer-before-zoteros-cache.md). Measure encoded size and encoding time against the existing PNG output on representative excerpts to verify the benefit.

Existing durable PNG assets and their links retain compatibility. Zotero-owned PNG sources and frozen Child Note snapshots retain their ownership and meaning. Image format, validated bytes, MIME type, and filename extension must agree at display and storage boundaries.

Zotero fallback PNGs retain their original validated bytes when used or saved by ZotLit. Their freshness remains uncertain, and they remain separate from validated generated cache entries. This keeps the failure-recovery path independent of WebP encoding. New generated WebP assets and retained PNG assets therefore coexist.

Use the common container check on cache reads. Before retaining a vault asset or publishing bytes from an external source, verify usable pixels as well: PNG must inflate to the declared scanlines and WebP must decode to its declared image. New bytes from the current process's encoder already represent decoded pixels. An external result whose host cannot decode it stays unavailable. Node tests supply a decoder scoped to the case. ### Encoder and decoder checks

Request WebP at quality 1 for Chromium's lossless encoder. Identify the actual payload before using it. If the canvas host supplied PNG, preserve PNG metadata throughout the cache, display, and vault asset. Validate agreement between container, MIME type, and extension. Older records without format metadata can derive it from the container. Encode once and reuse those bytes.

Validate lossless WebP at the chunk level and reject lossy, truncated, animated, or inconsistent containers. Cap encoded bytes, dimensions, and estimated RGBA bytes before decoding because a small payload can declare a large bitmap. Container validation leaves pixel verification to the host decoder on durable external assets. Pass the bytes to `createImageBitmap` through a Blob, close a successful bitmap, and refuse output when the host cannot decode it.

The committed 8 × 8 fixture came from `canvas.toBlob(callback, "image/webp", 1)` in Electron 43.3.0 (Chromium 150.0.7871.212). It includes the ICC profile written by Chromium and samples alpha at 0, 17, 128, 200, 254, and 255. The fixture uses browser-safe base64 decoding so the Electron trial and Node tests share it. Header-only and padded containers test structural and size checks independently of the real decoder.

Use deterministic crop content for size, timing, and pixel comparisons. An opaque WebP round trip must match the render buffer and lossless PNG byte for byte. For translucent content, compare alpha exactly and account for canvas premultiplication when comparing colors. Where WebCodecs is available, compare its raw decoded samples exactly for both patterns. Include a lossy payload as a negative control. The recorded M4 Pro run's slowest single encode was 17.5 ms. WebP reduced text, ink, and image crop sizes, with small overhead on nearly empty crops. The trial can write its measurements to the configured output path. [Encoder trial](../../../../packages/annotations/src/core/excerpt-image/encode.browser-test.ts) · [Pixel check trial](../../../../packages/annotations/src/core/excerpt-image/webp-pixels.browser-test.ts)

Keep derivative bytes in device-local IndexedDB apart from vault assets. The format-version check tracks the IndexedDB schema constant. Read a legacy record by its detected container. Observe the transaction result even when an individual request rejects. Keep image updates, accounting, and deletion of references in one transaction. Suppress cooperative task yields until IndexedDB requests finish because the transaction closes when its request microtasks drain. The Chromium store test inserts raw records, interrupts eviction and reference updates, and exercises the actual upgrade path.
