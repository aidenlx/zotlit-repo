# File Link Capture patches `window.open`

A Literature Note already carries Attachment File Links: `zt.attachments[].fileLink`, `zt.annotations[].fileLink` with its `#page=N` anchor, and Attachment Import's blocked-source fallback all write a `file://` URI. Clicking one leaves Obsidian for the system PDF app, and for a path outside the vault Obsidian's main process asks for confirmation first. ZotLit already opens the same file in Obsidian's own reader from four other surfaces. File Link Capture closes that gap by taking the click, and it takes it by patching the global `window.open`.

There is no other complete place to take it. Read against Obsidian 1.14.2: reading view renders `<a class="external-link">`, but Live Preview renders no anchor at all — it keeps the raw Markdown and reads the URL off the CodeMirror syntax tree through `getClickableTokenAt`. Reading view, Live Preview, Properties, and Bases all end at `window.open(href, target)`, and no `Workspace` event fires on a left click. A delegated DOM handler therefore covers reading view and misses Live Preview, which would make one link behave two ways in one note.

Capture claims a click only when `AttachmentResolver` resolves the path to an Obsidian-Openable Attachment. `target === "_external"` is handed to the original before any resolution runs, because that is how Obsidian's own "Open in default browser" item reaches `window.open`. That pass-through is the whole per-link escape hatch: the context menu entry already exists, so Capture adds no menu item of its own.

## Considered Options

- **A delegated click on `a.external-link[href^="file:"]`** (rejected): touches no global, but Live Preview has no anchor to delegate from, so the same link would open in Obsidian in reading view and in the system app while editing.
- **Changing what `fileLink` emits** (rejected): fixes nothing for a note already rendered, and ADR 0043 argues against writing a device-local path into a durable artifact — which `fileLink` already does, and which capture leaves alone rather than entrenching further.
- **Patching `window.open`** (chosen): the one symbol all four click paths share, narrowed to a single scheme and a single resolution rule. (A second scheme joined later; see Consequences.)

## Consequences

- Capture depends on four undocumented behaviours: that every external-link click ends at the bare global `window.open`, that `"_external"` is the target of Obsidian's own "Open in default browser" item, the `file:`-prefixed linkpath that `Vault.getFileByPath` falls through to the external file manager, and `eState.subpath` as the PDF view's page-jump input. All four are re-verified when `minAppVersion` moves. Where each one is read in the bundle is in `git show 452c5b598^:docs/pdf-annotation-probes.md`, and the click cases in `packages/e2e/src/annotation-links.e2e.ts` (Live Preview, reading view and a Properties value) check the first in the running app.
- One patch covers pop-out windows. Obsidian's link handlers call the bare global `window.open` — the reason `activeWindow` exists as a separate global — so a click in a pop-out reaches the same patch. The one per-window `containerEl.win.open(...)` in the bundle is the plugin browser's community-page item, which passes `"_external"` and is handed back anyway.
- An in-vault Attachment is found by the casing the clicked link carries. The resolver case-folds per ADR 0035, so a hand-written link whose casing differs from the vault's is claimed, and then `Vault.fileMap`, which holds the real casing, misses it. The user sees the missing-file notice rather than a wrong file. A link ZotLit wrote carries the Zotero row's own casing, which is what the index was built from.
- Selecting the Annotation a link came from is [ADR 0046](./0046-landing-on-a-mark-is-an-ephemeral-state-contract-read-at-the-leaf.md), which reads an Annotation Anchor off the ephemeral state at the leaf and makes the `fileLink` an Annotation renders its first caller.
- An in-vault Attachment is captured to its vault-relative path through `obsidianOpenPath()`, not to the `file:` form, so one file keeps one representation and the PDF annotation editor binds to it. That rule now has two callers.
- `AttachmentResolution` carries the openable verdict. The path index already holds the Attachment row when it builds an entry, so the two rules — is it ours, can Obsidian host it — travel together instead of being recomputed per click.
- A resolution of `pending`, which is what the resolver answers while the Zotero database cannot be read, hands the click back to the system handler. ZotLit does not claim a link it cannot yet identify. A resolved Attachment whose file has since gone shows a notice instead, because the claim was already made.
- The subpath passes through as written, so `#page=N` lands without any work of its own. Obsidian's `&annotation=<id>` names a PDF-native id, not a Zotero key, so it cannot carry a Zotero Annotation.
- Capture claims a second scheme: a Durable Annotation Link, Zotero's own `zotero://open/.../items/<key>?annotation=<key>`, the next step ADR 0046 names. It names the Attachment by key, so the resolver looks that Attachment up by its key — its file and its openable verdict in one answer — and the same openable rule applies. The Annotation key becomes the Anchor's Indexed Key, and the link's `page`, a printed label, rides along as `#page=N` only when it reads as a page number. Unlike a `file:` link, a known file that is not on disk still reaches Zotero: a second computer whose synced library never received the PDF opens the passage there, which is what makes the link durable. The reader reports a missing file as an outcome of the open itself, and the link is then handed to Zotero as written in place of a missing-file notice. No existence check runs ahead of the open, so a file that goes between the check and the open cannot strand the link. A link without a valid annotation key, and every `zotero://select`, stays Zotero's.
- Two Attachments can keep one file, and a path alone names only the one the index prefers. A link to the other one opens it in Obsidian's reader all the same, with its own Annotation selected: every open ZotLit makes names its Attachment beside the Annotation Anchor (`zt-attachment`), and the PDF view binds the Attachment the open named while that Attachment keeps the file on screen. A plain open — the file explorer, Obsidian's own quick switcher, a `file:` link — still names the file's Attachment by its path. Capture no longer hands such a link to Zotero.
- Capture is the entry point for links Obsidian rendered, not the place the decision lives. Every ZotLit place that opens an Attachment or follows a link — the page chip, the open-PDF command, the Literature Note file menu, the Library View, the Query View links, the quick switcher, the `open-attachment` protocol link and the Annotation View — opens it as an Open Target through one opener, which chooses between Obsidian's reader and Zotero and owns the Zotero fallback. The patch asks it whether to take a link and passes every link it declines. The opener hands Zotero a link with the `"_external"` target, which the patch passes untouched, so a fallback never loops back into Capture. An explicit "Open in Zotero" (`zotero://select`, the Citation Popover's Zotero reader, "show in Zotero") stays direct to Zotero.
- Capture warms the resolver's index as it installs. The index is built on the first lookup, and until it lands every lookup answers `pending`, which passes the click. A note's links are clicked before any PDF asks for the index, so without the warm-up the first click of a session would leave Obsidian.
- `reader.open-file-links` turns Capture off. The patch is still installed and still hands every call to the original, rather than being installed and removed as the setting moves — one fewer moving part, at the price of one property read per external link click.
- `reader.open-annotation-links` hands Durable Annotation Links alone back to Zotero. The opener's `follow` reads it per link, inside the branch that has already parsed one, and declines while it is off, so a `file:` link and every other `zotero:` link keep their path. Annotation hover stays enabled. The opener's keyed `open`, which the page chip (on Annotation View, query block and Reading Card cards), the Query View's annotation rows and the other ZotLit gestures use, reads the same rule for an Annotation target: while either setting is off it hands the Annotation's Durable Annotation Link to Zotero without the index lookup. A page chip shows that link as its `href`, so users read it as an annotation link, and the setting promises that annotation links open in Zotero ([#1980](https://github.com/aidenlx/zotlit/issues/1980)). An Attachment target opens as before, since the open-PDF gestures name Obsidian's reader in their own label.

## Capture and gesture lifetime

Decide whether to claim the link synchronously before returning from the patched `window.open`. Pass through a named tab, split, or window pane. The empty target from Reading view, absent target from Live Preview, and `_blank` from Properties all select the current pane. Execute a claimed open on the plugin's scoped runner. In the capture tests, send the fallback through the current patched window member to prove that it passes through once. Read that same member after disposal to exercise restoration. [Capture](../../../../packages/annotations/src/desktop/attachment-open/capture.ts) · [Capture tests](../../../../packages/annotations/src/desktop/attachment-open/capture.test.ts)

Send picker rows through the Target Opener by Indexed Key. A gesture starts the open without waiting, and unload can end it while it waits for the Attachment index. A view sends the open through the plugin's view registry so replacing the initiating tab leaves the open running until plugin unload. [Open command](../../../../packages/annotations/src/desktop/attachment-open/actions.ts) · [View opener](../../../../packages/annotations/src/desktop/attachment-open/view-opener.ts)

A keyed open waits up to five seconds for the first Attachment index. This gives a click during startup a chance to use the local PDF. A failed build leaves the first index pending. The resolver can retry it on a later lookup. If the index is still pending after the wait, the opener sends the target to Zotero. Link Capture uses the index it has when the click arrives because the decision must finish before it returns. [Target Opener](../../../../packages/annotations/src/desktop/attachment-open/open-target.ts) · [Attachment Resolver](../../../../packages/plugin-services/src/obsidian/attachment-resolver/service.ts)

The host supplies the PDF reader and can bring its Annotation View forward with the file. The opener reports which destination accepted the target. It shows a missing-file notice for a captured Attachment File Link because the link provides no Zotero identity for fallback. Reader and system errors produce a failure notice. Interrupting the pending open ends it without opening a destination or showing a notice. [Target Opener tests](../../../../packages/annotations/src/desktop/attachment-open/open-target.test.ts)

The ephemeral fragment has no separate library segment. The Attachment and Annotation keys therefore carry the library in their Indexed Key. A keyed Annotation gesture converts its zero-based page index to the fragment's one-based page. A Durable Annotation Link can supply a numeric page label for that fallback. When the reader finds the Annotation, it uses the Annotation's actual page. [Target Opener](../../../../packages/annotations/src/desktop/attachment-open/open-target.ts) · [ADR 0046](./0046-landing-on-a-mark-is-an-ephemeral-state-contract-read-at-the-leaf.md)

The opener tests seed a Zotero database and use the real Attachment Resolver. The test ports record reader opens, system opens, and notices. The shared-path rows exercise the distinction between the named Attachment and the path index's preferred Attachment. The fixture propagates the test's clock into the runtime so tests can advance the index wait and dispose the opener while a gesture is pending. [Opener fixture](../../../../packages/annotations/src/__fixtures__/attachment-open.ts)

The page chip builds an Open Target from the Attachment and Annotation Indexed Keys. Its Backlink extracts the bare Zotero keys and group ID from those identities when it builds the Zotero URI. [Card actions](../../../../packages/annotations/src/desktop/annot-view/actions.tsx)

The desktop feature mounts the shared Open Target command on the plugin's view registry. A reader open can replace the initiating tab, so that lifetime allows the open to finish after the tab closes. File Link Capture uses the same Target Opener. [Desktop feature](../../../../packages/annotations/src/desktop/feature.ts)

The card's page chip identifies the type, page and colour. It can use the full card as the drag image, offset to the grab point. When the chip has a Backlink, its press uses the shared Open Target action and takes the pane choice from the modifier key. This gives a local PDF the normal reader path. With no Backlink, the chip leaves a click to the card's selection gesture. [Page chip](../../../../packages/annotations/src/desktop/annot-view/Annotation.tsx)

File Link Capture controls the destination of a clicked Attachment File Link. The Durable Annotation Link setting separately chooses whether the PDF Reader opens with its Annotation selected or Zotero handles the link.

### Durable Annotation Link proof

Exercise click routes from note surfaces, Annotation View chips,
embedded Annotation cards, and Obsidian's open-in-default-app action.
The chips use the same Durable Annotation Link and follow its Reader
setting. A link can still land on the Attachment and page when the
Annotation has gone. If the PDF file is missing, forward the link to
Zotero without also showing a missing-file notice. Keep the legacy
device-local route working.

Run each link gesture and its cleanup together. Record URLs handed off
to Zotero without launching the local app. Reload ZotLit over an
installed recorder so its startup patch wraps the recorder. Suppress
native anchor navigation separately without recording it, so a chip
that misses the intended route fails the proof. Verify that Capture
warms the Attachment index before any PDF opens. Poll readiness without
performing a lookup because a lookup can itself start the build.
