# @zotlit/obsidian

ZotLit's desktop Obsidian host. Feature code lives in packages; this app composes it and owns Worker entries, settings migrations, build configuration, and integration tests across features. The root package map identifies feature owners.

## Host wiring

- `src/features.ts` orders feature registrations and startup hooks; `src/host.ts` sets the page/menu order and composes settings with `withHost` from `src/services/settings/`.
- `src/zt-main.ts` uses `shellEntry` to import `src/zt-body.ts` once the layout is ready. Keep the static entry free of Effect and feature code. `src/link-actions.ts` lists early `obsidian://` actions; its typecheck keeps entry and body registrations aligned.
- `src/zt-body.ts` starts the host through `shellStart`, with the Electron preflight and installer notice. The preflight reads `process.versions.electron` before any service exists, in the desktop-only plugin, so the file is exempt from the Node-globals lint rule. For lifecycle or registration changes, read [plugin-shell](../../packages/plugin-shell/AGENTS.md).
- `src/capabilities.ts` wires ZoteroReads and citation parsing to the Worker entries in `src/services/zotero-reads/` and `src/services/citation-parse/`. For RPC changes, read [zotero-reads](../../packages/zotero-reads/AGENTS.md). It builds `LibrarySource` of `@zotlit/plugin-services` (the Device Override of the library source, the online library's Worker, key, sync schedule and status) over the ports of `src/services/zotero-reads/library-source.ts`: the Worker start from `ZoteroReadsWebWorker` and the Resource Pack, Electron's first system language, the window focus, Obsidian's secret storage and the removal of the pool directory in the origin private file system. `ZoteroReads` reads the facade client of `LibrarySource` when the device chose the online library, and `workerClient()` of the Zotero file source otherwise. `src/services/zotero-reads/library-source.test.ts` runs the product path with the built Worker texts and the fake Zotero API.
- `src/worker/zotero-reads-web-root.ts` is the Web Worker root of ZoteroReads (the Worker zone): it composes `serveZoteroReadsWeb` with the Query Job runner of `@zotlit/query-views`, a Node-free meter and no file writer. `scripts/web-worker.ts` gives its build, for the Mobile floor (`chrome108`, `safari16.4`) with the Web Worker row of the runtime table, and the build of the Temporal piece (`@zotlit/plugin-kernel/worker/temporal-piece.ts`). `vite.config.ts` embeds both in `main.js` as functions that return the text deflated (raw deflate, level 9) in base64 (`form: "deflated"` of `scripts/embedded-worker.ts`), so start-up scans about 40 % of the bytes of the text and nothing evaluates them. The build parses each root (`scripts/worker-loads.ts`, with the scopes of `scripts/worker-scope.ts`) and refuses one that imports a module its runtime does not give (a Node built-in counts as one in each root) or a computed name through `import()`. A Web Worker has no `require`, so the build refuses any reference to a free `require`, to `globalThis.require` or to `self.require`, except `typeof require`. The build also refuses an `importScripts` call with other arguments than the one piece global read from `self`, `globalThis` or a variable that holds only `self`. Each Web Worker text starts with a notice (`scripts/worker-notices.ts`): each bundled package directory with its version, its licence documents (regular files named `LICENSE`, `LICENCE` or `COPYING`, with an optional `-<suffix>` and an optional `.md` or `.txt`), its `NOTICE*` files, and the legal comments of the bundled code, which the build moves out of the code. A package with no licence document takes the file of `licences/manifest.json` at the workspace root for its name and version; a `NOTICE*` file alone is not a licence. The build refuses a package with neither. The sqlite-wasm glue and the jieba-wasm glue read the Worker's location for `import.meta.url`, so the bundle holds no copy of either wasm. `src/services/zotero-reads/web-worker-client.ts` is the `ZoteroReadsWebWorker` service: `readWasm` reads the `sqlite-engine` entry and refuses one whose version differs from the bundled glue (`__SQLITE_ENGINE_VERSION__`, the installed `@sqlite.org/sqlite-wasm`, from `scripts/sqlite-engine.ts`); `start` imports the loader and the texts, inflates each text into a Blob (`embedded-text.ts`, `DecompressionStream`), and gives them with the wasm to `startWebWorker`, or fails with `WebWorkerCodeUnreadable`. Its test runs `start` on the built texts. The root rethrows a failed start (as a failed load of the Temporal piece) outside the promise, so the host gets an error event, and then closes the Worker. `scripts/web-worker.test.ts` runs the built texts in a Node thread with the post-floor globals removed, on memory storage: a sync of the scenario library from the fake Zotero Web API, a read of each kind, the Chinese Segmenter from a test pack, ZotLit Queries and view jobs, and a storage without OPFS. With `Temporal` removed the thread loads the piece once; with `Temporal` kept it loads none, and the Worker text holds no polyfill code. The inflated texts equal the built roots, and a piece that throws fails the first request. The thread's `fetch` is relayed to the test thread and it has a small `Response`, because Node's own use APIs that the test removes.
- `src/services/citations/`, `notes/`, and `template-workbench/` hold tests across feature packages. Change production behavior in the owning package.
- `src/__fixtures__/mobile-host/` composes a Node-free host over stub ports. `tsconfig.mobile.json` type-checks it, `scripts/check-mobile-host.ts` runs the runtime check on its closure, which reaches no desktop-zone file and no Electron, and `src/mobile-host.test.ts` checks its service order. `vite.mobile.config.ts` builds it with browser conditions as `dist-mobile/main.js`, and `pnpm check:bundle` holds that bundle to the Mobile renderer row of `packages/scripts/lib/runtime-table.ts`. No release ships it.

Packages do not import this app. Features register their service and settings types through declaration merging. Use `/obsidian-services` for services/features and `/obsidian-settings` for settings pages. Settings are flat dot-notation keys in `PluginSettings` from `@zotlit/plugin-services/obsidian/settings/service.ts`; `src/services/settings/schema.ts` composes the feature slices.

## Commands

Use the root build/test/lint commands. App-specific operations:

- `pnpm --filter @zotlit/obsidian dev` watches the development build.
- `I18N_DEV_SERVER=true pnpm --filter @zotlit/obsidian dev` serves Language Packs locally on port 9092 (or set a port number). Development versions have no Resource Release, so non-English development needs this server; otherwise the bundled English pack remains active.
- `pnpm --filter @zotlit/obsidian analyze` writes `bundle-stats.html`; `ANALYZE=json` produces `bundle-stats.json`.

The production build writes `dist/package/`, then the publish shell builds `dist/main.js` and `dist/styles.css`. The development build writes `dist-dev/` directly. The owners are `vite.config.ts` and `@zotlit/scripts/shell/host-build`; product metadata is in `packages/scripts/lib/shell/plugins.ts`.

## UI and runtime

Preact provides the UI runtime through React compatibility aliases. For UI changes, run `/obsidian-css`; for rendered behavior, use `/obsidian-debug`. The latter uses the host desktop; `pnpm e2e` uses a Run Container. See [the e2e guide](../../packages/e2e/AGENTS.md) for selection and host admission.

For view integration, read [ADR 0082](docs/adr/0082-obsidian-views-read-effect-services-through-view-atoms.md) and `packages/obsidian-kit/src/view-atoms.ts`. Feature-local models and gestures belong with their feature. The PDF Annotation Marks and Creation Toolbar use vanilla DOM; the Mark Popup has one Preact root on Obsidian's popover ([ADR 0042](docs/adr/0042-the-surfaces-inside-the-pdf-reader-are-vanilla-dom-on-obsidians-popover.md), [ADR 0065](docs/adr/0065-the-mark-popup-is-one-preact-root-on-obsidians-popover.md)).

Effect imports resolve through `effectEntry` in `packages/plugin-kernel/scripts/effect-entry.ts`. Renderer entries use Chromium scheduling and the plugin logger; Workers use `effect-worker.ts` without the renderer logger. `effectEntryCheck` checks the built entry. SQL runs in the ZoteroReads Worker: `scripts/renderer-sql-check.ts` fails a renderer build that bundles `drizzle-orm` and prints the import chain, so renderer code imports the Drizzle-free modules of `@zotlit/item-query` and `@zotlit/db`. The optional `pnpm e2e:performance` checks timing budgets on the reference MacBook; ordinary E2E checks correctness and reports timings.

For logging setup, read `packages/plugin-services/src/obsidian/log/service.ts` and `packages/plugin-kernel/src/effect-log.ts`.

## Messages and CLI

Messages come from `@zotlit/plugin-messages/messages.ts`. Turbo generates the facade and Language Packs; use `pnpm --filter @zotlit/plugin-messages generate:language-packs` when bypassing Turbo. Run `/i18n-ui-text` for wording and `/inlang-i18n` for format/runtime mechanics.

For a `zotlit:*` command, read `packages/obsidian-kit/src/cli-command.ts` and `cli-params.ts`; `packages/query-views/src/desktop/item-query/decode.ts` shows parameter decoding. CLI guide sources live beside their handlers.

For a CLI schema or downloadable resource, read `packages/template-workbench/src/core/cli/schema.ts`, [ADR 0019](../../docs/adr/0019-runtime-assets-ship-on-a-parallel-resource-release.md), and `packages/scripts/lib/shell/templates/.github/workflows/plugin-release.yml` for the pinned Resource Release contract.

## Tests and private APIs

Run `pnpm exec vitest run path/to/file.test.ts` from this app for a single file, or `pnpm exec vitest` for watch mode. Direct runs need generated dependencies; use Turbo first. Workspace packages are read from source, without a package build.

`vitest.config.ts` resolves `obsidian` to the mock in `packages/obsidian-kit/src/__mocks__/obsidian.ts` and `@effect/vitest` through the plugin's Effect wrapper. The wrapper supplies the browser scheduler and plugin logger as well as TestClock/TestConsole. Capture plugin logs with `captureLogRecords` or `forwardLogRecords` from `packages/plugin-kernel/src/__fixtures__/log-capture.ts`; a local `Logger.layer` only sees the Effect it is supplied to.

Private Obsidian API declarations live in `packages/obsidian-kit/src/typings/obsidian-ex.d.ts`; update the mock separately. A mock used by message calls needs `getLanguage()` returning the fixture locale. Obsidian's global `sleep` is absent in Node; use `delay` from `@std/async` for a timed wait, or `yieldToMain` from `@zotlit/plugin-kernel/yield-to-main.ts` for a macrotask yield without timer clamping.
