# The SEO sitemap is keyed off the typed `AppRoutes` union

> **Superseded by the TanStack Start migration (spec [#846](https://github.com/aidenlx/zotlit/issues/846)).**
> `app/sitemap.ts`, `typedRoutes` in `next.config.ts`, the generated
> `@next/routes` union, and `next typegen` are all gone. The sitemap now keys
> its table off `FileRouteTypes["to"]` in `src/lib/sitemap.ts`; see
> [AGENTS.md](../../AGENTS.md) § "SEO and machine endpoints". The drift-safety
> reasoning below still holds — only the source of the route union changed.
> Kept for the record.

`app/sitemap.ts` enumerates URLs through an exhaustive `Record<StaticRoutes, [Entry]> & Record<DynamicRoutes, Entry[]>`, where `StaticRoutes`/`DynamicRoutes` are split out of `AppRoutes` (the union imported from the generated `@next/routes`). To get that union we enabled `typedRoutes: true` in `next.config.ts` and added a `"@next/*"` path to `tsconfig.json`. A flat array concatenation of the four route groups would have been ~15 lines shorter and needs no config change, which is the default AGENTS.md would point at.

We chose the typed table for two reasons. First, drift safety: adding a new page route grows `AppRoutes`, which leaves a key missing from the `Record` and fails the typecheck until the route is placed in the sitemap or explicitly excluded — a flat concat drifts silently. Second, consistency: the sibling `mx-repo` website sitemap uses this exact shape, and both sites are maintained together.

The zotlit table is deliberately simpler than the sibling's: it has no `Private`/`Public` split because zotlit has no auth pages. Its only non-indexable endpoints (`llms*`, `og`, `rss`, `api/search`) are route handlers, which Next classifies as `AppRouteHandlerRoutes`, not `AppRoutes` — so they are excluded by construction rather than by a maintained disallow list. The v1 permalinks are likewise `RedirectRoutes` and never appear.

## Consequences

- Enabling `typedRoutes` makes every `<Link href>` and router call in the app statically checked. A typo or a link to a removed route now fails the build instead of 404-ing at runtime.
- `lastModified` is emitted only where a real date exists — changelog entries carry frontmatter `date`; docs pages and blog posts carry their file's last commit date from git (fumadocs-mdx's `last-modified` plugin), a post falling back to its `date`; the home page and the section indexes have none, so they ship without `<lastmod>` rather than a fabricated build-time timestamp.
- `priority` and `changeFrequency` are omitted: Google and Bing ignore both in sitemaps, so they would be inert noise.
- On a fumadocs major bump, re-check that `page.url` and the collection `date` fields still type as used; the `@next/routes` union is regenerated by `next typegen` (wired into the `codegen` script).

## TanStack Start sitemap and page metadata

The current sitemap uses `FileRouteTypes["to"]` and subtracts the named machine routes. Adding a route leaves a missing Record entry until it is listed or excluded. The machine route list itself is checked against the route union. Publish the docs index once through its static entry, and use collection entries for nested pages. Read Git modification days from the compiled body. A blog post falls back to its ISO publication day. A native Chinese edition can have its own timestamp, and a missing edition does not supply a Chinese timestamp.

Merge head tags by identity, so a route supplies only the fields that differ from the root. Keep a full title verbatim when it already names the site. Otherwise append the site name or use the site name alone. Set the canonical, social image dimensions, MIME and alt, and publish any alternate media links. An article carries author and publication metadata, and a page head can contain several JSON-LD objects.

Publish technical docs as TechArticle, use the HTML page as `mainEntityOfPage`, and include an absolute social image URL, actual content language, and available ISO dates. Keep the first and last Git days distinct for docs and lessons. Map only the maintainer handle to a GitHub profile. Other authors retain display names. FAQ data uses the visible question name and accepted answer text. Serialize JSON-LD so a literal less-than sign cannot terminate the enclosing script element.
