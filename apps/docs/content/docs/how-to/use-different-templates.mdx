Add a profile for the paper type, set a condition on its <UiLabel name={m.workbench_tab_match()} /> tab, and ZotLit picks it for every matching item. This page makes a profile for books.

A profile decides a literature note's name, folder, properties, and body. A new profile starts as a copy of the Default profile. Before you start, edit the Default profile once, as in [Customize a template](/docs/how-to/customize-a-template).

<Steps>
  <Step>
    ### Add a profile [#add-profile]

    In Obsidian, open <SettingsPath page={m.settings_page_profiles()} />. In the header of the <UiLabel name={m.settings_profile_other_heading()} /> list, select <UiLabel name={m.settings_profile_add()} />.

    ![The Literature note profiles settings page with the Add profile button in the header of Other profiles outlined in red](/img/how-to/use-different-templates-1-add-profile.webp)

    The dialog <UiLabel name={m.settings_profile_add()} /> opens.

  </Step>
  <Step>
    ### Name it and choose its folder [#name-folder]

    In <UiLabel name={m.settings_profile_name_name()} />, type `Books`. In <UiLabel name={m.settings_profile_folder_name()} />, type `literatures/books`, then select <UiLabel name={m.settings_profile_add()} />. The folder is optional. Leave it empty to use the Default profile's folder.

    ![The Add profile dialog with the name Books and the folder literatures/books outlined in red](/img/how-to/use-different-templates-2-name-folder.webp)

    The profile opens in the editor as **Books · Profile**. ZotLit writes `zotlit-profile.books.md` into your template folder. The name is the label you see in lists. The profile's identity is an ID inside the file, so renaming the file changes nothing. See [Profiles](/docs/reference/templates/how-templates-work#profiles).

  </Step>
  <Step>
    ### Edit its note text and properties [#edit]

    The editor opens on <UiLabel name={m.workbench_tab_name_and_folder()} />. The <UiLabel name={m.settings_profile_folder_name()} /> reads `literatures/books`. Edit <UiLabel name={m.workbench_tab_note()} /> and <UiLabel name={m.workbench_tab_properties()} /> as in [Customize a template](/docs/how-to/customize-a-template#insert-field) and [Configure properties](/docs/how-to/configure-frontmatter-properties).

    ![The Name and folder tab of the Books profile with the Literature note folder field, set to literatures/books, outlined in red](/img/how-to/use-different-templates-3-folder.webp)

    Only notes made with this profile use these settings.

  </Step>
  <Step>
    ### Set the condition that selects it [#match]

    Select <UiLabel name={m.workbench_tab_match()} />. The tab starts with one empty condition row. Choose <UiLabel name={m.workbench_filter_field_item_type()} />, leave the middle choice on **is**, and choose **Book**.

    ![The Match tab with one condition, Item type is Book, outlined in red](/img/how-to/use-different-templates-4-match.webp)

    The row reads **Item type is Book**. A row with no value selects nothing. Above the conditions, choose how they combine: <UiLabel name={m.workbench_match_match_all()} />, <UiLabel name={m.workbench_match_match_any()} />, or <UiLabel name={m.workbench_match_match_none()} />. The conditions are the same as the filter of a [Query View](/docs/how-to/use-query-files#filter). See [Profile Match](/docs/reference/templates/profile-match).

  </Step>
  <Step>
    ### Check the condition against an item [#check]

    Select <UiLabel name={m.workbench_choose_match_item()} /> under the conditions and choose a book.

    ![The Match tab after choosing a book, with the result Matches selected item outlined in red](/img/how-to/use-different-templates-5-check.webp)

    The tab reports <UiLabel name={m.workbench_match_result_yes()} />. For any other item type it reports <UiLabel name={m.workbench_match_result_no()} />. On the settings page, the profile's row reads <UiLabel name={m.settings_profile_match_status({ state: "evaluable" })} />.

  </Step>
  <Step>
    ### Move a note to the profile [#switch]

    ZotLit uses the profile for every new note whose item matches. To move a note you already have, open it, open the command palette, and run <Command inline name={m.command_switch_literature_note_profile_name()} />.

    ![The list of profiles opened by Switch literature note profile, with the row Books and its note path outlined in red](/img/how-to/use-different-templates-6-switch.webp)

    The list shows each profile with its folder and the path the note would have. Select **Books** to give the note that profile. Existing notes keep the profile that made them until you switch them.

  </Step>
</Steps>

## When two profiles match [#overlap]

Two profiles can match the same item, and ZotLit does not choose for you when they do. The picker opens and reports <UiLabel name={m.modal_profile_problem_overlap({ profiles: "…" })} />. Its search box reads <UiLabel name={m.modal_profile_overlap_placeholder()} />, and every candidate that matches the item carries <UiLabel name={m.modal_profile_match_candidate()} />.

Pick the profile you meant to use, or dismiss the picker to cancel the note. Narrowing the conditions on the <UiLabel name={m.workbench_tab_match()} /> tab is the durable fix.

## When you pick a profile by hand [#manual]

A profile you choose for the current operation wins over Profile Match, whatever the conditions say. [Profiles](/docs/reference/templates/how-templates-work#profiles) holds the order ZotLit tries when it selects one.

Your choice covers that one operation. The note records the profile that made it, and later updates read that record instead of the conditions.

## Share the profile as one file [#share]

A profile is a single document, so you can move it to another vault as one file, with the partials it calls travelling inside it. The [Profile document](/docs/reference/templates/profile-document) reference describes every key inside it.

<Steps>
  <Step>
    ### Share the profile [#share-profile]

    On the profile's row, open <UiLabel name={m.workbench_more_actions()} /> and select <UiLabel name={m.settings_profile_share()} />.

    ![The menu on the Books row with Share outlined in red](/img/how-to/use-different-templates-7-share-menu.webp)

    The share dialog collects the document and the partials it appears to call.

  </Step>
  <Step>
    ### Choose what the file carries [#share-options]

    Under <UiLabel name={m.profile_share_partials()} />, clear any partial you do not want to send. <UiLabel name={m.profile_share_include_match()} /> carries the Profile Match to the receiving vault, and <UiLabel name={m.profile_share_folders()} /> adds your note folders. Select <UiLabel name={m.profile_share_copy()} /> to put the file on the clipboard, or <UiLabel name={m.profile_share_save()} /> to write it into a folder you choose.

    ![The Share Books dialog with Copy to clipboard outlined in red](/img/how-to/use-different-templates-8-share-dialog.webp)

    Both produce the same single document. The notice <UiLabel name={m.profile_share_copied()} /> confirms the copy.

  </Step>
  <Step>
    ### Import it in the receiving vault [#import]

    Run <Command inline name={m.command_import_profile_name()} />, or select the import button in the header of the <UiLabel name={m.settings_profile_other_heading()} /> list. Then choose <UiLabel name={m.profile_import_clipboard()} /> or <UiLabel name={m.profile_import_file()} />.

    ![The Import profile list with Read from clipboard outlined in red](/img/how-to/use-different-templates-9-import-source.webp)

  </Step>
  <Step>
    ### Read what the import dialog reports [#import-dialog]

    The dialog shows the profile, its folder and citation style, and the incoming Profile Match as a filter expression. <UiLabel name={m.profile_import_include_match()} /> imports the Match with the profile, so it selects notes in this vault too. Turn it off to keep the profile for manual selection only. Select <UiLabel name={m.profile_import_confirm()} /> to write the profile.

    ![The Import profile dialog with the Import match conditions switch outlined in red above the folder and citation style](/img/how-to/use-different-templates-10-import-dialog.webp)

    <UiLabel name={m.profile_import_none_changed()} /> When the shared profile carries no Match, the dialog reads <UiLabel name={m.profile_match_absent()} /> and hides the switch.

  </Step>
</Steps>
