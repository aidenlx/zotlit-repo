To make a literature note before changing its template, start with <LessonLink slug="connect-zotero-to-obsidian" />.

Open the Default profile, insert a Zotero field in the note text, and check the result in the live <UiLabel name={m.workbench_result_heading()} />. Edits save by themselves and apply to new notes. Nothing here changes your Zotero library.

The thing you edit is a **profile**: one file in your template folder (`templates` by default), `zotlit-profile.default.md` for the Default profile. See [How templates work](/docs/reference/templates/how-templates-work).

<Steps>
  <Step>
    ### Open the profile [#open-profile]

    In Obsidian, open <SettingsPath page={m.settings_page_profiles()} />. On the <UiLabel name={m.settings_profile_default_name()} /> row, select the pencil button, <UiLabel name={m.settings_profile_edit()} />.

    ![The Literature note profiles settings page, with the pencil button on the Default row outlined in red](/img/how-to/customize-a-template-1-open-profile.webp)

    The Template Workbench opens as a new tab named **Default · Profile**, with the note text on the left and a <UiLabel name={m.workbench_result_heading()} /> on the right. The first time, ZotLit creates `zotlit-profile.default.md` in your template folder.

  </Step>
  <Step>
    ### Choose a paper to preview [#choose-paper]

    Select <UiLabel name={m.workbench_choose_item()} /> above the tabs, then select a paper under <UiLabel name={m.workbench_recently_updated()} />, or search for one with <UiLabel name={m.workbench_search_zotero()} />.

    ![The Choose item list open over the editor, with the row for Rougier et al. (2014), Ten Simple Rules for Better Figures, outlined in red](/img/how-to/customize-a-template-2-choose-paper.webp)

    The line above the tabs names the paper, and the <UiLabel name={m.workbench_result_heading()} /> fills with that paper's properties, links, and annotations.

  </Step>
  <Step>
    ### Open the Note tab [#tabs]

    Select <UiLabel name={m.workbench_tab_note()} />. Each tab edits one part of the profile: <UiLabel name={m.workbench_tab_note()} /> is the body of the note, <UiLabel name={m.workbench_tab_properties()} /> is covered in [Configure frontmatter properties](/docs/how-to/configure-frontmatter-properties), and <UiLabel name={m.workbench_tab_name_and_folder()} /> and <UiLabel name={m.workbench_tab_match()} /> are covered in [Use a different template for different notes](/docs/how-to/use-different-templates).

    ![The Note tab of the profile editor, with the row of tabs outlined in red, the note text on the left, and the note preview on the right](/img/how-to/customize-a-template-3-note-tab.webp)

    The editor shows the note text: a heading with the title, a line with links, and an **Annotations** section. The preview beside it shows the finished note for your paper.

  </Step>
  <Step>
    ### Insert a Zotero field [#insert-field]

    In the note text, place the cursor where the value should go, for example after `Published in: `. Select <UiLabel name={m.workbench_view_fields()} /> in the header, select the row **Published in**, and select <UiLabel name={m.workbench_fields_insert()} /> on the card that opens.

    ![The Fields list open at the right edge, with the card for the Published in field showing its template path and the Insert button outlined in red](/img/how-to/customize-a-template-4-insert-field.webp)

    `{{ zt.publicationTitle }}` appears at the cursor and the list closes. ZotLit replaces each field in double braces with the paper's own value when it writes the note. To find a field before you open the editor, see [Explore template data](/docs/how-to/explore-template-data).

  </Step>
  <Step>
    ### Check the preview [#check-preview]

    Look at the <UiLabel name={m.workbench_result_heading()} />.

    ![The note preview with the new line Published in: PLOS Computational Biology outlined in red](/img/how-to/customize-a-template-5-preview.webp)

    The note now reads **Published in: PLOS Computational Biology**. The preview updates as you type, and Obsidian's Undo and Redo work.

  </Step>
  <Step>
    ### Update a note you already have [#apply]

    New notes use your edited profile at once. A note that already exists keeps its text until you update it. Open the note, open the command palette, and run <Command inline name={m.command_update_note_name()} />.

    ![The command palette with ZotLit: Update literature note outlined in red, over an open literature note](/img/how-to/customize-a-template-6-update-note.webp)

    The notice <UiLabel name={m.notice_updated_note()} /> appears. <Command inline name={m.command_overwrite_note_name()} /> replaces the whole note body after a confirmation.

  </Step>
</Steps>

<Accordions multiple>
<Accordion title="If something looks different" id="fixes">

- **An error when ZotLit creates the file, the first time** → select the retry action beside the error message.
- **The preview is empty or shows no paper** → select <UiLabel name={m.workbench_choose_item()} /> and choose a paper from your library or a built-in example.
- **The preview fails** → retry the preview or pick another paper with <UiLabel name={m.workbench_choose_item()} />. You can keep editing.
- **The Fields list says "Select a place in the template to insert a field."** → select a place in the note text, then open <UiLabel name={m.workbench_view_fields()} /> again.
- **A note did not change after you edited the body** → run <Command inline name={m.command_update_note_name()} /> to refresh properties. If your profile has no managed block, ZotLit shows <UiLabel name={m.notice_updated_note_no_managed_block()} /> Body edits reach new notes; to rebuild an existing note's body, run <Command inline name={m.command_overwrite_note_name()} />.
- **An Eta template does nothing** → Eta templates require the <UiLabel name={m.settings_template_js_enable_name()} /> setting. Without it, Eta templates stay inert and do not fall back to built-in text. See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates).
- **A partial's call is marked** <UiLabel name={m.workbench_partial_missing()} /> → the partial was renamed or deleted. Edit the partial name in your template call or create the partial file again.
- **A partial's fields come out empty** → the Liquid call is missing its data argument; write `{% render "name" with zt as zt %}`.

</Accordion>
<Accordion title="Edit the profile of a note you already have" id="existing-note">

Open the literature note and run the command <Command inline name={m.template_workbench_open_layout()} />, or select <UiLabel name={m.template_workbench_open_layout()} /> from the note's file menu. The Template Workbench View opens with that note's paper already selected.

</Accordion>
<Accordion title="Change the text a citation inserts" id="citation-text">

- Open <SettingsPath page={m.settings_page_citations()} />. On the <UiLabel name={m.settings_citation_text_name()} /> row, select the pencil button, tooltip <UiLabel name={m.settings_citation_text_open()} /> (or run the command <Command inline name={m.command_customize_citation_text_name()} />).
  The file `zotlit-citation.md` opens on the <UiLabel name={m.workbench_tab_citation()} /> tab. (If you have not customized it before, the row reads <UiLabel name={m.settings_template_using_default()} /> and ZotLit creates the file from the built-in text first.)
- The <UiLabel name={m.workbench_citation_result_heading()} /> shows how your citation will look. From the pane menu, choose <UiLabel name={m.template_workbench_preview_main_citation()} /> or <UiLabel name={m.template_workbench_preview_alt_citation()} /> to test both types, or choose <UiLabel name={m.template_workbench_use_example()} /> to load built-in citation shapes.
- One template controls both main and alternate citations; [`zt.variant`](/docs/reference/templates/data#citation-variant) identifies which one was requested. See [Fields a citation template reads](/docs/reference/templates/data#citation-templates).
- Citations already in your notes are plain text and stay as written. Edits apply to the next citation you insert.
- To discard your changes, select the rotate button, tooltip <UiLabel name={m.settings_template_reset()} />, on the <UiLabel name={m.settings_citation_text_name()} /> row. Confirm <UiLabel name={m.settings_citation_text_reset_confirm_title()} /> to move your file to Obsidian's trash.

</Accordion>
<Accordion title="Use one piece of text in several profiles" id="share-a-partial">

- A **partial** is a reusable template file (`zotlit-partial.<name>.md`) that any profile or citation template can call by name.
- To create one, open <SettingsPath page={m.settings_page_profiles()} setting={m.settings_partials_heading()} /> and select <UiLabel name={m.settings_partial_add()} />. Alternatively, select text inside the workbench editor, right-click it, and choose <UiLabel name={m.template_workbench_extract_partial()} />.
- Call the partial in Liquid using `{% render "authors" with zt as zt %}` (typing `{% render "` lists your partials and inserts the arguments automatically). In Eta, call `<%~ include("authors", zt) %>`.
- For details on naming and parameters, see [Calling a partial](/docs/reference/templates/syntax#calling-a-partial).

</Accordion>
<Accordion title="Go back to the built-in template" id="restore-built-in">

On the <UiLabel name={m.settings_profile_document_name()} /> row in <SettingsPath />, select <UiLabel name={m.settings_profile_document_restore()} />. Confirm <UiLabel name={m.settings_profile_document_restore_title()} />. ZotLit moves your profile file to Obsidian's trash, where you can recover it if needed. Existing notes keep their current content until updated.

</Accordion>
</Accordions>
