import { Card, Cards } from "fumadocs-ui/components/card";

import { Command } from "@/components/command";
import { UiLabel } from "@/components/ui-label";
import { m } from "@/paraglide/messages.js";

Open the <UiLabel name={m.workbench_tab_properties()} /> tab, select <UiLabel name={m.workbench_properties_add()} />, and link a property to a Zotero field. Then run <Command inline name={m.command_update_note_metadata_name()} /> to bring it into a note you already have.

Properties are the block at the top of a note, shown in Obsidian as the **Properties** list. Each profile keeps its own rules, and edits save by themselves. ZotLit ships four: `title`, `related`, `collections`, and `citekey`.

Before you start, open the Default profile and choose a paper, as in [Customize a template](/docs/how-to/customize-a-template#open-profile). This page uses `zt.publicationTitle`, the journal name from [Explore template data](/docs/how-to/explore-template-data).

<Steps>
  <Step>
    ### Open the Properties tab [#open-properties]

    In the profile editor, select <UiLabel name={m.workbench_tab_properties()} />.

    ![The Properties tab of the profile editor, outlined in red, with one row for each of title, related, collections, and citekey](/img/how-to/configure-frontmatter-properties-1-properties-tab.webp)

    The list shows a row for each property, with the value for your paper. The <UiLabel name={m.workbench_result_heading()} /> shows the same properties.

  </Step>
  <Step>
    ### Add a property [#add-property]

    Select <UiLabel name={m.workbench_properties_add()} /> under the list.

    ![The Add a property button under the list of properties, outlined in red](/img/how-to/configure-frontmatter-properties-2-add-property.webp)

    A new row opens at the bottom with <UiLabel name={m.workbench_properties_name()} />, <UiLabel name={m.workbench_properties_expression()} />, and <UiLabel name={m.workbench_properties_merge()} />.

  </Step>
  <Step>
    ### Name the property [#name]

    In <UiLabel name={m.workbench_properties_name()} />, type `journal`.

    ![The Property name field of the new row with journal typed in, outlined in red](/img/how-to/configure-frontmatter-properties-3-name.webp)

    The row's title changes to **journal**. The name is the key ZotLit writes at the top of the note.

  </Step>
  <Step>
    ### Choose its value [#value]

    Leave <UiLabel name={m.workbench_properties_expression()} /> on <UiLabel name={m.workbench_properties_format_value()} />. In the box under it, replace `zt.title` with `zt.publicationTitle`. A list of fields opens as you type; press Escape to close it.

    ![The value box of the journal row holding zt.publicationTitle, outlined in red](/img/how-to/configure-frontmatter-properties-4-value.webp)

    The row now shows the paper's journal, **PLOS Computational Biology**. The other choices for the value are <UiLabel name={m.workbench_properties_format_text()} /> and <UiLabel name={m.workbench_properties_format_rule()} />.

  </Step>
  <Step>
    ### Choose what happens on update [#merge]

    Under <UiLabel name={m.workbench_properties_merge()} />, keep <UiLabel name={m.workbench_properties_merge_replace()} />.

    ![The When the note is updated choice set to Replace the existing value, outlined in red](/img/how-to/configure-frontmatter-properties-5-merge.webp)

    ZotLit then overwrites the property each time a note updates. <UiLabel name={m.workbench_properties_merge_append()} /> adds new items and keeps the ones already in the note. <UiLabel name={m.workbench_properties_merge_keep()} /> writes the property only while it is empty. See [Merge strategies](/docs/reference/templates/frontmatter#merge-strategies).

  </Step>
  <Step>
    ### Check the preview [#check-preview]

    Look at the **Properties** list in the <UiLabel name={m.workbench_result_heading()} />.

    ![The note preview with the new row journal, PLOS Computational Biology, outlined in red](/img/how-to/configure-frontmatter-properties-6-preview.webp)

    The preview shows a row **journal** with **PLOS Computational Biology**.

  </Step>
  <Step>
    ### Update a note you already have [#apply]

    New notes get the property when ZotLit creates them. A note that already exists changes only when you update it. Open the note, open the command palette, and run <Command inline name={m.command_update_note_metadata_name()} />.

    ![The command palette with ZotLit: Update literature note metadata outlined in red](/img/how-to/configure-frontmatter-properties-7-update-command.webp)

    The note's **Properties** list gains **journal** with **PLOS Computational Biology**.

    ![The Properties list of the literature note, with the journal and tags rows outlined in red](/img/how-to/configure-frontmatter-properties-8-note-properties.webp)

  </Step>
</Steps>

## Add Zotero tags to your notes [#zotero-tags]

Add one more property to keep the tags of a paper in Zotero in the note's `tags` property. Repeat steps 2 and 3 with these values, then update the note.

| Input                                                  | Value                                                                               |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| <UiLabel name={m.workbench_properties_name()} />       | `tags`                                                                              |
| <UiLabel name={m.workbench_properties_expression()} /> | <UiLabel name={m.workbench_properties_format_value()} />, `zt.tags \| obsidian_tag` |
| <UiLabel name={m.workbench_properties_merge()} />      | <UiLabel name={m.workbench_properties_merge_replace()} />                           |

![The tags property row with zt.tags piped to obsidian_tag, outlined in red](/img/how-to/configure-frontmatter-properties-9-tags.webp)

Choose <UiLabel name={m.workbench_properties_merge_append()} /> instead to keep tags you added by hand in Obsidian. The `obsidian_tag` filter turns spaces and other characters into what Obsidian allows in a tag. For example, Zotero tags named `Methodology` and `Open Access` become:

```yaml
tags:
  - Methodology
  - Open_Access
```

See the [`obsidian_tag` filter reference](/docs/reference/templates/syntax#obsidian-tag) for every rule.

<Accordions multiple>
<Accordion title="If something looks different" id="fixes">

- **A row is marked** <UiLabel name={m.workbench_properties_row_problem()} /> → the expression cannot be used. The <UiLabel name={m.workbench_problems_heading()} /> area names what went wrong and offers <UiLabel name={m.workbench_problems_where_entry()} /> to open the row. See [Validation](/docs/reference/templates/frontmatter#validation) and [Edit a profile as Markdown](/docs/how-to/edit-a-profile-as-markdown#problems).
- **A property written in JavaScript does nothing** → it is inert while <UiLabel name={m.settings_template_js_enable_name()} /> are off on that device, and ZotLit reports the affected fields: <UiLabel name={m.notice_frontmatter_js_inert({ fields: "…" })} /> See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates).

</Accordion>
<Accordion title="Edit, remove, or reorder a property" id="edit-or-reorder">

Select a property row to edit it. Use <UiLabel name={m.workbench_properties_remove()} /> to remove it.

The order of the rows sets the order of the keys when ZotLit creates a new note. Drag the handle (<UiLabel name={m.workbench_drag_to_reorder()} />) at the start of a row, or select the handle and press `Alt+Arrow Up` or `Alt+Arrow Down`.

Reordering does not change notes that already exist: a key already in a note keeps its place. To reorder the properties of one note, drag the property type icon in Obsidian's properties panel. The note needs two or more properties.

</Accordion>
<Accordion title="Set properties with an agent" id="agent">

An agent with the [ZotLit template skill](/docs/install-skill) can add a managed `tags` property with the expression `zt.tags | obsidian_tag`. The [Template Workbench CLI](/docs/reference/template-workbench-cli) lets it configure the property and test the rendered result.

</Accordion>
</Accordions>
